# 0.6.0 后台重编码：本地验证与性能

> NeoForge 来源版历史记录：本文的性能数据及验证数量不代表 Fabric 1.21.1 移植版，Fabric 版尚未通过 ATM10 验证。

日期：2026-11-10。状态：本地验证与 ATM10 正式服务端核验完成；真实服务器性能和活动窗口内存见 ATM_BACKGROUND_0.6.0.md。

## 保存行为

游戏内 CQS 前台只将完整普通 NBT 做一次 zlib 压缩，经原有同步 COW 协议确认落盘，再提交后台空间优化请求。后台读取已提交记录，在锁外试算共享状态与精确区段编码，发布时复核句柄身份、区块 generation、codec 与字典 generation。新保存、删除及关闭重开使旧任务失效；字典变化重新投递。字典与编码载荷仍一起持久化，前台保存时间戳不变。

固定 1–2 个低优先级工作线程；最多 128 个区域任务，每区 1,024 个去重槽位，一批最多 32 块，同区域串行。区域静默 500 ms 后领取，保持请求到达顺序。排队只持槽位及弱引用，不持 NBT。停止时协作取消并等待当前操作安全结束，不 interrupt 文件通道。

flush 不等待后台完成。关闭、淘汰、停服或队列饱和可以放弃压缩任务；原始数据已持久化，下次打开区域可重新尝试。已有 MCA 保存与迁移仍同步编码。状态/区段/CQS 格式不变。

## 完整文件大小

每维度 20 个区域、20,480 块，以真实运行时保存方式写入；包含 CQS 索引、字典、碎片和 owner。新保存生成新的确认时间戳，后台和两次重开保持该时间戳，不声称沿用原 MCA 时间戳。此流式验证允许前台与后台重叠，4 GiB 最大堆、两个后台线程；其耗时不用于上面的隔离性能对照。

| 维度 | 原 MCA（MiB） | 前台结束（MiB） | 后台完成并正常 flush（MiB） | 显式整理后（MiB） | 正常 flush 后较原 MCA |
|---|---:|---:|---:|---:|---:|
| 主世界 | 281.64 | 227.52 | 227.53 | 191.54 | -19.21% |
| 地狱 | 283.37 | 227.27 | 227.29 | 204.93 | -19.79% |
| 暮色森林 | 141.52 | 98.43 | 98.44 | 89.12 | -30.44% |

| 维度 | 0.6.0 字节 | 0.5.2 已验证紧凑样本字节 |
|---|---:|---:|
| 主世界 | 200,840,704 | 200,847,360 |

显式整理后的压缩率与旧版紧凑样本基本相同，但它不是当前自动流程必定立即得到的文件大小。普通 flush 仅在浪费至少 1 MiB 且达到 25% 时整理；本次仍有低于门槛的内部空洞。后台 drain 本身不触发全区域强制整理。前台结束的文件也可能已包含其他区域的后台结果，不能作为纯原始 NBT 文件大小。

## 内存边界和采样

队列固定 int[1024] 与位图的主体容量约 528 KiB（128 区域满队列，不含对象开销），每个打开的后台区域另有 8 KiB attempted generation 数组，最多 64 份/存储实例，约 512 KiB/实例。各维度实例累计；这些是数据结构容量，不是实测 retained size。既有全局读取字典缓存仍按最大堆 1/32、16–128 MiB、最多 64 份的估算权重淘汰。

活动任务另有私有字典、输入、候选 NBT 和压缩缓冲。压缩快照最多 16 MiB、NBT 解析计额 64 MiB；线程数量按每线程 768 MiB、最多半堆、至少一个估算。该估算不是内存预分配或硬上限。

本地地狱流式验证中额外采集约 39.03 秒：两个后台线程均有执行样本，扣除每线程首个可能夹带历史的分配样本后，分别观察到约 1,234.74 MiB 和 1,142.40 MiB 的分配权重。它们是窗口内分配通量估算，不能当作常驻占用。

该窗口整个验证 JVM 的工作集观测峰值 1,550.54 MiB，私有提交峰值 2,407.99 MiB；GC 边界堆已用为 35.47–1,264.85 MiB，0 个 SystemGC 事件。包含样本读取、前台验证、字典、后台候选和待回收垃圾，既不是 JVM 全生命周期峰值，也不是本模组新增内存。该本地采样没有对应的无模组活动窗口，不能给出 ATM10 常驻增量；另行完成的 ATM10 六轮进程内存对照见 `ATM_BACKGROUND_0.6.0.md`，同样不能将整个 JVM 差额等同于模组 retained size。较早的主世界 15 秒录制已落在重开验证尾段，扣除首样本后无后台分配，不用于声称后台活动内存。

JFR 只加在全量正确性验证进程中，没有加在保存对照微基准中。它可能影响全量验证的耗时；没有主动 GC、live histogram 或 heap dump。

## 正确性验证

- 177 项 Java 回归：0 failures / errors / skipped。覆盖过期任务、新写入、删除、字典变化、关闭重开、有限排队、取消、停服不中断通道、FIFO、故障锁和四阶段持久化故障恢复。
- 4 项真实 NeoForge GameTest 全通过；故障注入后的后台服务清理只存在于测试源码，不进入正式 JAR。
- 60 个区域、61,440 块：立即读取、后台完成后、两次独立重开的完整 NBT 和确认时间戳一致。
- 每维度一整个区域共 3,072 块，经独立 Python 导出，再由 Java 比较完整 NBT 与时间戳；三个维度都实际覆盖 codec 5 完整区段引用。
- 全样本结束 queued=0、active=0、skipped=0、dropped=0、failed=false；优化成功数分别 20,088 / 18,882 / 15,433，其余完整数据保持原样。
- 正式 JAR 无 GameTest、ATM 验证及生成基准探针；生产源码指纹在测试前后相同。未进行硬件断电测试或长期多人服负载测试。
